# Clog Companion — Design

RuneLite plugin that ranks Collection Log slots by how quickly they can realistically be
obtained, lets the player filter and sort them, and can roll a random target with a
spinning animation. Published to the RuneLite Plugin Hub from `mablack01/clog-companion`.

## Goals

- Answer "which collection log slots should I go for next?" with **accurate** time estimates.
  A clue-casket unique must rate as Medium/Long even though looting the casket is trivial,
  because the estimate includes acquiring and solving the clue.
- Side panel with filters (tier, category, obtained, requirements met, text search) and sort
  (estimated time, drop rate, name).
- "Roll" a random slot from the currently filtered pool, with a fast→slow spin animation.
- Stay well under the Plugin Hub AI-review ceiling (200k tokens of `src/main/java`).

## Non-goals (prototype)

- No network calls at runtime. All data ships in the jar.
- No per-boss combat helpers of any kind (Hub-forbidden).
- No export/import of obtained state to third-party sites.

## Key constraints

- Java 11, Gradle, `runelite/example-plugin` structure, BSD-2-Clause, no new dependencies.
- The Hub reviewer counts **only non-comment code under `src/main/java`**. `src/main/resources`
  and `src/test` are free. All bulk data therefore lives in JSON resources; Java holds logic only.
- Follow `AGENTS.md` (from the template): injected `Gson`, `gameval` constants, no reflection,
  no client-thread I/O, cleanup in `shutDown()`.

## Architecture

```
com.clogcompanion
├── ClogCompanionPlugin        wiring only: load data, register panel/listeners, shutdown
├── ClogCompanionConfig        @ConfigGroup("clog-companion")
├── model/                     plain data, no RuneLite deps
│   ├── ClogSource             one collection-log entry page (Zulrah, Master Treasure Trails…)
│   ├── ClogItem               one slot: (source, item) + drop rate
│   ├── Requirements           skills, quests, diaries
│   ├── Tier                   EASY, MEDIUM, LONG, GRIND, UNRATED
│   └── Category               BOSSES, RAIDS, CLUES, MINIGAMES, OTHER
├── data/
│   ├── ClogDataset            loads + joins the two JSON resources; indexes by id/source
│   └── (resources) clog-items.json, clog-sources.json
├── engine/                    pure logic, unit-tested with fixtures
│   ├── DifficultyEngine       expected minutes + tier for a slot
│   ├── RequirementChecker     AccountState → met / unmet reasons
│   ├── ClogFilter             composable predicates
│   └── ClogSorter             comparators
├── account/
│   ├── AccountState           immutable snapshot: levels, quest states, diary flags
│   ├── AccountStateReader     builds AccountState from Client (login, StatChanged, VarbitChanged)
│   └── ObtainedTracker        widget scan on COLLECTION_DRAW_LIST + chat message; per-RSN persist
└── ui/
    ├── ClogPanel              PluginPanel: filter bar + list
    ├── ClogItemRow            one card
    └── RollDialog             spin animation + result
```

Dependency direction: `ui → engine/account → model/data`. Nothing in `model`, `data`, or
`engine` imports `net.runelite.api.Client`; they take `AccountState` values instead so
they can be tested without a client.

## Data

### `src/main/resources/com/clogcompanion/clog-sources.json` — curated

One entry per collection-log page. This is where human judgement lives.

```json
{
  "id": "master_treasure_trails",
  "name": "Master Treasure Trails",
  "category": "CLUES",
  "minutesPerAttempt": 25,
  "setupMinutes": 0,
  "requirements": {
    "skills": { "SLAYER": 93 },
    "quests": ["REGICIDE"],
    "diaries": ["DIARY_DESERT_HARD"]
  },
  "notes": "Per-attempt includes acquiring one master clue and solving it."
}
```

- `minutesPerAttempt` — wall-clock minutes for one roll of the drop table, **including**
  everything needed to get that roll (travel, clue acquisition, minigame round, boss kill).
- `setupMinutes` — one-time cost before the first attempt (unlocks, gear, quest chain time
  not captured by `requirements`). Often 0.
- `requirements.quests` reference `net.runelite.api.Quest` enum names; `diaries` reference
  `net.runelite.api.Varbits` `DIARY_*` names; `skills` reference `net.runelite.api.Skill`
  names. The plugin resolves them at runtime with `Quest.getState(client)` and
  `client.getVarbitValue(...)`; no custom varbit map.
- Either time field may be `null` while curation is in progress → every slot under that
  source is `UNRATED`. The data-integrity test reports the count so it's visible in CI
  output but does not fail the build.

### `src/main/resources/com/clogcompanion/clog-items.json` — generated

One entry per in-game slot. Regenerated by `tools/generate_clog_data.py`; never hand-edited.

```json
{
  "id": "master_treasure_trails:3rd_age_longsword",
  "sourceId": "master_treasure_trails",
  "itemId": 12426,
  "name": "3rd age longsword",
  "rate": 0.0000345,
  "rateText": "1/28,988",
  "wikiUrl": "https://oldschool.runescape.wiki/w/3rd_age_longsword"
}
```

- `rate` is per attempt of its source. `1.0` means guaranteed on first attempt (quest
  rewards, shop items). `null` means unknown → treated as `UNRATED`.
- Slots that exist in more than one entry in-game (e.g. Dragon pickaxe under several bosses)
  are separate records, exactly like the in-game log.

### `tools/generate_clog_data.py`

- Fetches the OSRS Wiki `Collection log` page and each entry page through the MediaWiki API,
  parses entries per tab and drop rates per item, and writes `clog-items.json`.
- Prints every entry that has no curated `clog-sources.json` record and a stub block to paste,
  so curation never falls silently behind.
- Records the wiki revision ids it was generated from in a header comment of the JSON
  (`_generated` key) for reproducibility.
- Lives outside `src/`; costs nothing toward the review budget.

## Difficulty model

```
attempts(rate, mode) = mode == EXPECTED ? 1 / rate
                     : ln(1 - p) / ln(1 - rate)        // LIKELY: p = 0.5 (median)
expectedMinutes(slot) = setupMinutes + attempts × minutesPerAttempt
```

Tier thresholds on `expectedMinutes` (config-overridable):

| Tier   | Upper bound |
|--------|-------------|
| EASY   | ≤ 60 min    |
| MEDIUM | ≤ 5 h       |
| LONG   | ≤ 25 h      |
| GRIND  | > 25 h      |

`mode` is a config item (default `EXPECTED`). `UNRATED` when rate or time is missing.
Rates of `1.0` short-circuit to `setupMinutes + minutesPerAttempt`.

## Account state

- `AccountStateReader` snapshots real skill levels, every `Quest` state, and each `DIARY_*`
  varbit on `GameStateChanged(LOGGED_IN)`, `StatChanged`, and `VarbitChanged` (debounced to
  once per game tick via a dirty flag). Produces an immutable `AccountState`.
- `RequirementChecker.check(Requirements, AccountState)` returns `Unmet` reasons
  (`"Slayer 93 (have 87)"`, `"Regicide not completed"`) or empty when met.

## Obtained tracking

- On `ScriptPostFired` with `ScriptID.COLLECTION_DRAW_LIST`, read the current page's
  `InterfaceID.Collection.ITEMS_CONTENTS` children: item id + obtained flag (opacity 0 ⇒
  obtained, same signal core's pet reader uses). Header text identifies the entry.
- On `ChatMessage` matching `New item added to your collection log: (.*)`, mark every slot
  with that name obtained (all entries; the game does the same).
- Persist `Set<slotId>` per RSN in `ConfigManager` under `clog-companion.obtained.<rsn>`
  as a JSON array. Loaded on login; cleared from memory on logout.
- Slots never seen are `UNKNOWN`, not unobtained. The panel shows a banner "Open your
  Collection Log to sync" until at least one page has been scanned for the current RSN.

## UI

- `ClogPanel` (`PluginPanel` + nav button with `icon.png`):
  - Filter bar: tier toggle chips, category dropdown, checkboxes *Hide obtained* and
    *Meets requirements*, search field. Filter state is kept in `ClogFilter` and persisted
    in config so it survives restarts.
  - Sort dropdown: *Fastest first* (default), *Rarest*, *A–Z*.
  - List: `ClogItemRow` cards — item icon via `ItemManager.getImage`, name, source name,
    `rateText`, `~2h 10m`, tier badge, unmet-requirement line in red, wiki link via
    `LinkBrowser`. Rendered with a lazy viewport (only build rows for visible page; page
    size 50 with "Show more") to keep Swing cheap for 1,500 slots.
  - Pinned target strip at top when a roll result is accepted.
- `RollDialog`: "Roll" cycles through the filtered pool. `javax.swing.Timer` with delay
  easing from 40 ms → 400 ms over ~3 s, showing the icon + name of each pass, then lands
  on a uniformly random slot (chosen up front; the animation is cosmetic). Buttons:
  *Go for it* (pins) / *Roll again*. Empty pool → button disabled with a tooltip.

## Config (`@ConfigGroup("clog-companion")`)

| key | type | default |
|-----|------|---------|
| `estimateMode` | enum EXPECTED / LIKELY | EXPECTED |
| `easyMaxMinutes` / `mediumMaxMinutes` / `longMaxMinutes` | int | 60 / 300 / 1500 |
| `hideObtained` | boolean | true |
| `onlyMeetsRequirements` | boolean | false |
| `pinnedSlot` | hidden string | "" |

## Error handling

- Malformed or missing JSON → plugin logs at `warn`, panel shows "Data failed to load" and
  nothing else; no crash.
- Unknown quest/diary/skill names in the overlay are caught by the data-integrity test at
  build time, and additionally skipped with a `debug` log at runtime.
- Widget scan wrapped defensively: null widget or unexpected child layout → skip the page.

## Testing

- `src/test` (free for review budget):
  - `DifficultyEngineTest` — thresholds, both modes, rate 1.0, null → UNRATED, clue-casket
    example lands MEDIUM.
  - `RequirementCheckerTest` — met/unmet reasons for skills, quests, diaries.
  - `ClogFilterTest` / `ClogSorterTest` — predicate composition and ordering.
  - `ClogDatasetTest` — loads the real resources; every `sourceId` resolves; every
    quest/diary/skill name resolves to its enum/constant; prints UNRATED count.
  - `ObtainedTrackerTest` — chat-message parsing and persistence round-trip with a mocked
    `ConfigManager`.
- `tools/token-budget.py` (copied from flip-smart) + a GitHub Actions workflow that builds,
  tests, and fails if `src/main/java` exceeds `.github/token-ceiling`.
- Widget scanning and the panel are verified live on the dev client (`./gradlew run`).
